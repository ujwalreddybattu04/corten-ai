# Pharma record analysis and preview layout

Pharma Intelligence record titles, thumbnails and highlights open a record page with the API's dated facts, original source, available identifiers and fields. Missing values are shown as not listed. FDA action dates, trial record updates and news publication dates retain their different meanings.

Corten generates a concise analyst brief with Key facts, Forecast relevance and What to verify. A narrow follow-up gets a direct, short answer rather than repeating every section. The dedicated authenticated `/pharma/analysis/stream` endpoint resolves the canonical API record and checks it against the displayed snapshot before generation. Missing or changed records return a recovery message before the model is called. Full source evidence and the current question remain separate from bounded conversation history, avoiding the general chat path's shortening of long requests.

The server prompt separates reported facts from interpretation. It preserves the meaning of FDA action dates and trial record-update dates, copies scientific identifiers exactly, and avoids treating a supplemental action as a new product approval or an updated study as new results. Internal feed keys are excluded from model evidence. Missing source information is described as missing from the snapshot. Provider citation glyphs are normalized to the existing Markdown citation format across token boundaries. User-selected answer modes and configured provider fallback remain available. The endpoint shares generation rate limits with Search and requires a complete provider response before signalling success. This feature does not change Space agents or interpolation calculations.

Prompt design follows OpenAI's guidance to separate instructions, examples and reference context, and to specify audience, format and constraints. It uses the project's existing model provider; these practices do not require replacing it. [OpenAI prompt engineering guidance](https://developers.openai.com/api/docs/guides/prompt-engineering), [ChatGPT prompting guide](https://developers.openai.com/cookbook/examples/chatgpt/chatgpt_prompt_guide/chatgpt_prompt_guide).

Completed public-mode analyses use personal chat history and its existing account sync. Private-mode answers remain unsaved. Record snapshots are scoped by account, therapy and date window, bounded by storage size and a 24-hour lifetime. Direct links fall back to the existing read-only feed API; records outside the current capped feed show an explicit recovery path. Reloading a matching saved conversation avoids duplicate generation. Interrupted or failed responses are not persisted, and retries require an explicit user action. Deletion and concurrent edits are respected.

The record page now uses a reading column and a separate source panel. On smaller screens the source details collapse above the brief, and the follow-up composer fits the viewport. Completed personal conversations offer Continue in Search for broader research; record follow-ups use the supplied snapshot and do not claim fresh web evidence. Refresh brief generates a new interpretation of the same snapshot; Check updates remains the feed's freshness action.

The shared Search/Spaces artifact preview now reserves its desktop column so the answer and composer remain visible. Smaller screens use a full-screen preview, accessible controls and keyboard navigation. A dark presentation stylesheet is applied only inside the existing isolated preview sandbox. Original code, chart data and downloads remain unchanged; explicitly authored graphics may keep their source colors.

Validation covers record ownership, cache corruption and expiry, evidence bounds, native chat persistence, private mode, deletion and concurrent edits; browser checks cover navigation, follow-up context, citation indices, reload, errors, responsive layout, preview controls and unchanged downloads. Hosting verification and provider availability are recorded separately from controlled browser fixtures.
